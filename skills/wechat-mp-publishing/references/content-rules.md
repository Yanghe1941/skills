# 内容规律

这份是**一个订阅号连续运营两个月、约 55 篇的实测结论**，包括一次把推荐流量做归零的事故。
样本只有一个账号，数字不必照搬，但因果结构大概率通用。

## 一、先看账号有没有分发，再谈内容

这是整份文档最重要的一条，因为它决定了其余各条什么时候才有意义。

实测过的顺序错误：账号被限流之后，把内容类型、读者视角、配图风格、CTA 全部换掉重写，
结果阅读从个位数变成**更低的个位数**。

**推荐归零时，内容是无效变量。** 判断方法——后台「账号成长 → 内容助推」看
`Available Impressions`：

- **归零 + 近期阅读个位数** → 账号级限流。改内容没用，先停更
- **有额度** → 再往下看母题和标题

## 二、阅读量的主变量是「内容助推」，不是内容本身

把全部发布记录按有没有助推分组之后，结论很清楚：**助推不是充分条件，但看起来是必要条件**——
同样的助推额度，阅读可以从几十到一千多；但**没有助推的，一篇都没破过 250**。

正确的因果：**助推决定有没有流量进来，内容决定能不能接住。** 两个都要。

操作要点：

- 「仅 7 天内发表且符合规范的内容可助推」，**发完就推，过期作废**
- 额度来自平台奖励（粉丝数里程碑之类），用完就没有
- **不要无助推地日更**——额度会被摊薄。宁可每周 1–2 篇、每篇都推

两个容易被忽略的免费入口：

- **贴图**：后台自动为每篇文章生成贴图草稿，发布后优先推荐给非粉丝
- **搜一搜**：实测只贡献约 0.3% 阅读，却贡献约 **37% 的新增关注**——
  转化率最高的入口，通常完全没人优化

## 三、看分享率，不看阅读量

平台推荐能把单篇灌到两千阅读而分享率只有 0.17%，那是**不可复制**的。
真正跑通社交传播的那篇，1400 阅读 / 100 分享，分享率 7%。

实测里分享率最高的两篇都只有四五十阅读（8.7% / 6.0%）——**分享率和阅读量基本无关**。
复盘时按分享率排序，才看得出哪篇内容真的有人愿意转。

## 四、别把「选对母题」推成「每篇同一个母题」

单篇维度上，平台推荐确实偏好某一类母题（该账号是「全屋盘点 → 家底/钱/数量」，
单点功能类选题实测均值只有 43 阅读）。

**但把这条推到「每篇都落回同一个母题」，就是在制造同质化。** 见下一节。

## 五、⚠️ 会把账号做死的做法

实测事故：连续日更 23 篇，母题、正文结构、配图模板、CTA 全部同构，并如实声明了
「内容由 AI 生成」。结果账号被判定 **「低创作度内容」**，推荐流量**直接归零**：
断崖前还有几十阅读，之后连续多日每篇 4–5 阅读，昨日阅读同比上周 **−94%**，粉丝净减。

命中的判定条款有两条：

- **同质化内容，频繁发布高度相似内容，缺乏信息增量**
- **低价值 AIGC 内容**

**单篇质量高 ≠ 安全。** 那 23 篇每篇都有真实细节和具体数字——平台判的是**账号级模式**。

因此必须带的约束：

| 约束 | 理由 |
|---|---|
| 频率 ≤ 每周 1–2 篇，**绝不日更** | 「频繁发布」是判定要素 |
| 一次最多建 2–3 篇草稿 | 一口气产十篇必然同构 |
| 结构不能复用模板——长度、段落数、有没有小标题都要真的不一样 | 结构相似度是机器可测的 |
| 配图不要全用同一套模板 | 视觉统一对品牌是加分，对同质化判定是减分 |
| CTA 不要每篇一字不差 | |
| 母题要轮换 | 对应「缺乏信息增量」 |

被判定之后：

- **删文不能作为优化**（平台明确写了），别指望删稿救回来
- 停更 1–2 周，先打断「频繁发布」这个要素
- AI 声明继续如实填。问题不在声明本身，在「声明 AI + 高度同构 + 日更」的组合

## 六、发之前先问：这个号有没有自有读者

一个容易被阅读量盖住的数字：把**单篇阅读 ÷ 粉丝数**算一遍。

实测那个账号是 100 出头粉丝、单篇阅读个位数，**开封率 1~4%**。
粉丝会话推送是平台关不掉的——所以历史上那个几十的阅读中位数**全部来自推荐，
这个号从来没有过自有读者**。

这个比值低于 10% 的话，说明：

- 你的阅读完全依赖平台施舍，随时可以归零（而且实测就是会）
- 涨粉数字不代表触达。两个月 55 篇，粉丝净增 1
- **该考虑这个渠道是不是选错了**，而不是继续优化内容

## 七、其他实测结论

- **原样重发衰减约 6.5 倍**（1412 → 218）。同一母题可以反复写，但必须换角度重写
- **转载内容基本归零**
- **发布时段不是关键变量**。早 8 点和下午 5 点都出过 400+，也都出过 10 阅读
- **标题**：有效句式是「第一人称 + 具体场景 + 一个结果状态」，≤22 字，带具体数字；
  功能名进标题基本必死。**但这条的权重远低于第一、二节**——没有分发，标题写得再好也没用
